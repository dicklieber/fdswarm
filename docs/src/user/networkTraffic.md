# Network Traffic

Open **Config → Network Traffic** to see application traffic for this node and
the other known swarm nodes. No external monitoring service or Internet access
is required. The dialog refreshes every two seconds; remote data arrives with
the existing periodic status broadcasts.

The first summary shows traffic generated by the active reporting nodes, using
only their sent bytes. Do not add received bytes to this figure: each UDP
broadcast may be received by every node. Separate sections show each node's
traffic, address, instance ID and report age.

Measurements cover the swarm's UDP socket, built-in HTTP server and replication
HTTP client. Separate radio integrations such as rigctl and WSJT-X are excluded.

Traffic is separated into UDP status, UDP QSO, UDP other, HTTP QSO synchronization,
HTTP configuration synchronization and HTTP other. Rates are one-minute smoothed
averages in KiB/s, not exact totals over the previous 60 seconds. Totals are in
MiB since each node started. UDP event counts are packets; HTTP event counts are
client request attempts sent (including retries) and server requests received.
HTTP byte counts include bodies in both directions.
UDP other also includes received datagrams whose headers cannot be recognized.

Completed QSO downloads and downloads that added no QSOs help identify repeated
full-dataset synchronization that transfers data without changing the store.

UDP byte counts include the application's datagram header. HTTP byte counts are
observed as body chunks are consumed, preserving compressed transfer sizes and
counting bytes processed before a failed transfer. They exclude HTTP headers,
IP/TCP/UDP headers, retransmissions and Wi-Fi airtime. These are application-level
measurements; packet capture is needed for protocol overhead and actual network
utilization. Other HTTP traffic includes documentation, logs and API calls.

Nodes reporting no traffic metrics are marked unavailable rather than shown as
zero. Reports older than three broadcast periods (at least 30 seconds) are marked
stale; their historical totals remain visible but their rates are unavailable.
Stale and unavailable nodes are excluded from the swarm summary. Node restarts
reset their counters, and nodes removed from the known swarm disappear from the
summary, so it is not a permanent contest-wide accounting record.
